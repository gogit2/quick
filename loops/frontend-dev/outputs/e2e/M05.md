**Status: EXECUTED (iteration 4).** E2E-M05-01..08 ran on the mock with the Playwright MCP and passed; results are in `outputs/evidence/M05/result.json`. E2E-M05-09 is real-stack-only and is not run here. Iteration 4 also fixed `acknowledge-start` (it sent a JSON body, which the contract does not declare; the mock answered 415).

The mock is **stateless**: writes do not change later reads, and every `GET /api/plans` returns the same example plan for both `group=` values (id 1 "Focused morning", IN_PROGRESS, 09:00Z-11:00Z, 1 of 3 items done, `startNotified: false`). Screenshots: write them to `outputs/evidence/M05/` if the tool allows it; otherwise use `run-artifacts/playwright/` and record the path in `result.json`.

## E2E-M05-01 [smoke] - Build a plan from three items (US-PLN-01..04)

Steps
1. Navigate to `http://localhost:4300/plans`. `plans-title` shows "Plans".
2. Click `plans-create-button`. The builder opens.
3. Set `plans-form-title` = `Focused morning`, `plans-form-duration` = `90`, `plans-form-start` and `plans-form-end` (2026-10-16 09:00 to 11:00), `plans-form-priority` = `1`.
4. Click `plans-pick-tasks`, tick `plans-pick-task-1`. Click `plans-pick-habits`, tick `plans-pick-habit-1`. Click `plans-pick-learning`, tick `plans-pick-learning-1`.
5. Click `plans-form-save`. Captured request: `POST /api/plans`, body with `items` of length 3 (TASK, HABIT, LEARNING_RESOURCE), status 201.
6. Dialog closes, `GET /api/plans` runs again.
7. Screenshot `E2E-M05-01-builder-saved.png`. Console: no errors.

Note: pick through the checkbox `input` inside each `plans-pick-*` element (the host element ignores `.click()`).

## E2E-M05-07 - Start banner, once, and acknowledge (US-PLN-07, D-8)

Steps
1. Reload the app with the clock at its real value (before the plan window): `plans-start-banner` is absent (plan not started by app clock).
2. Call `window.__qfClock.setNow('2026-10-15T09:30:00Z')`. Within about 2 s `plans-start-banner` shows "Plan Focused morning has started". `plans-highlight-1` is present on the card when `/plans` is open.
3. Captured requests: `POST /api/plans/1/acknowledge-start` exactly once (body `{}`), status 200.
4. Wait 5 s more: still one banner, still one acknowledge call (no repeat).
5. Click `plans-start-banner-dismiss`: banner gone; `plans-highlight-1` gone.
6. Notifications off: set Settings `notificationsEnabled` = false (PUT /api/settings), reload, set clock again: POST acknowledge-start is sent, no `plans-start-banner`. Restore the setting afterwards. Note: the mock is stateless, so the PUT does not change the next GET; check the flag from the app state, not the reload.
