# E2E scenarios - M06 Dashboard (frontend-dev)

Run against the Prism mock (`scripts/mock.sh start`, port 4010) and the dev server
(`scripts/frontend.sh start --api http://localhost:4010`, port 4300) with the Playwright MCP.
The mock is stateless: a POST does not change later GETs, so the mock never returns a changed dashboard.

Data-testids used: `nav-dashboard`, `dashboard-title`, `dashboard-greeting`,
`dashboard-quick-add-task|habit|learning|plan`, `dashboard-metric-tasks`, `dashboard-tasks-due-today`,
`dashboard-tasks-overdue`, `dashboard-completion-percent`, `dashboard-metric-habits`, `dashboard-habits-done`,
`dashboard-metric-plans`, `dashboard-plans-active`, `dashboard-plans-upcoming`, `dashboard-plans-completed`,
`dashboard-metric-learning`, `dashboard-learning-in-progress`, `dashboard-learning-milestones`,
`dashboard-today-tasks`, `dashboard-task-1`, `dashboard-task-complete-1`, `dashboard-overdue-tasks`,
`dashboard-overdue-2`, `dashboard-overdue-marker-2`, `dashboard-habits`, `dashboard-habit-1`,
`dashboard-habit-toggle-1`, `dashboard-habit-streak-1`, `dashboard-learning`, `dashboard-recent-milestone-1`,
`dashboard-plans`, `dashboard-plan-1`, `dashboard-plan-rest-1`, `dashboard-plan-progress-1`,
`dashboard-plan-item-toggle-2`, `dashboard-plan-item-2`, `tasks-form-cancel` (task dialog reused).

7. `dashboard-plans`: `dashboard-plan-1` ("Focused morning") with `dashboard-plan-rest-1` and `dashboard-plan-progress-1`.
8. `dashboard-learning`: `dashboard-recent-milestone-1` ("Finish chapter 3").
9. `browser_console_messages`: no errors (only Vite and Angular dev-mode logs).
Result: PASSED. Screenshot: `run-artifacts/playwright/E2E-M06-01-dashboard.png`.

## E2E-M06-03 Quick-add buttons open the dialogs and refresh the dashboard
1. Click `dashboard-quick-add-task`: dialog "New task" opens. Cancel (`tasks-form-cancel`): dialog closes, no request.
2. Click `dashboard-quick-add-habit`: dialog "New habit" opens. Cancel: closes.
3. Click `dashboard-quick-add-learning`: dialog "New learning resource" opens. Cancel: closes.
4. Click `dashboard-quick-add-plan`: dialog "Create plan" (plan builder) opens. Cancel: closes.
5. Save path: `dashboard-quick-add-task`, title "Dashboard quick add check", Save. Request sent: `POST /api/tasks` with `{"title":"Dashboard quick add check","description":null,"status":"TODO","priority":"MEDIUM","dueDate":null}`. Dialog closes, then `GET /api/dashboard` (dashboard reload).
Console: no errors.
Result: PASSED.

## E2E-M06-04 Habit toggle and plan item toggle send the right requests; dashboard reloads
1. Click the checkbox input of `dashboard-habit-toggle-1` (not done): `POST /api/habits/1/completions` with `{}`, then `GET /api/dashboard`.
2. Click the checkbox input of `dashboard-plan-item-toggle-2` (not done): `PUT /api/plans/1/items/2` with `{"done":true}`, then `GET /api/dashboard`.
Note (mock artifact): the stateless mock returns the same flags, so the checkboxes keep the toggled DOM state. The real stack changes the flags on success.
Result: PASSED (requests and reloads verified). Screenshot: shares `E2E-M06-01-dashboard.png` (state after toggles not captured separately).

## E2E-M06-05 Rest time changes with the clock override
1. With the app clock override `window.__qfClock.setNow('2026-10-15T09:30:00Z')`, `dashboard-plan-rest-1` reads "Rest 1h 29m 59s" (plan window 09:00Z-11:00Z).
2. `window.__qfClock.setNow('2026-10-15T09:31:00Z')`: `dashboard-plan-rest-1` reads "Rest 1h 28m 58s". The rest time updates with the clock.
Result: PASSED. Screenshot: shares `E2E-M06-01-dashboard.png`.
