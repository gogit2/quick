# E2E scenarios - M01 Foundation (frontend)

Source: `specs/001-quickflow/acceptance.md` section M01. Executed with the Playwright MCP against the Prism mock
(`scripts/mock.sh start`, port 4010) and the dev server (`scripts/frontend.sh start --api http://localhost:4010`, port 4300).
The mock is stateless: POST/PUT do not change later GETs. Items marked `[real-stack-only]` are written here and executed by the verifier.

## E2E-M01-01 [smoke] Six nav links open their page and highlight it

1. `browser_navigate` http://localhost:4300/
2. Expect URL `/dashboard` (start page of the mock settings), `dashboard-title` visible.
3. For each link `nav-dashboard`, `nav-tasks`, `nav-habits`, `nav-learning`, `nav-plans`, `nav-settings`: click it.
4. After each click: URL is `/<page>`, `<page>-title` is visible, the nav link has class `active`.
5. Reload (navigate to the same URL): the same page and active item remain.
- Screenshot: `run-artifacts/playwright/E2E-M01-02-tasks-empty.png` (Tasks, nav active).

## E2E-M01-02 Placeholder pages show their empty state

1. Open `/tasks`, `/habits`, `/learning`, `/plans` in turn.
2. Each page shows `<page>-empty-state` with `<page>-empty-add-button`.
- testids: `tasks-empty-state`, `tasks-empty-add-button`, `habits-empty-state`, `habits-empty-add-button`, `learning-empty-state`, `learning-empty-add-button`, `plans-empty-state`, `plans-empty-add-button`.

## E2E-M01-03 Settings form, save and saved message

1. Open `/settings`. Request `GET /api/settings` returns 200 and the 5 fields are filled.
2. Fields: `settings-display-name`, `settings-email`, `settings-time-zone`, `settings-notifications`, `settings-start-page`.
3. Click `settings-save-button`. Request `PUT /api/settings` returns 200 (`browser_network_requests`).
4. `settings-saved-message` ("Settings saved") is visible.
- Screenshot: `run-artifacts/playwright/E2E-M01-03-settings.png`.
- `[real-stack-only]` part: after a reload, the saved values are shown (the mock returns fixed data, so the stored values cannot be proven on the mock).

## E2E-M01-04 `/` redirects to the start page

1. Open `/`. The app redirects to the route of `defaultStartPage` (mock: DASHBOARD, so `/dashboard`).
- `[real-stack-only]`: change the start page to Tasks in Settings, save, reload `/` and expect `/tasks`. The mock cannot show a non-DASHBOARD start page.

## Error and empty-state checks `[real-stack-only]`

- Settings save with a server `fieldErrors` response shows the message under the field (`mat-error`). The mock always returns 200.
- Settings GET failure shows `settings-error-message`.
