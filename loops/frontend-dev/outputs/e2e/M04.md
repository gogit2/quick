# E2E scenarios - M04 Learning (frontend-dev)

Executed with the Playwright MCP (0.0.40) against the Prism mock (`scripts/mock.sh start`, :4010) and the Angular dev server (`scripts/frontend.sh start --api http://localhost:4010`, :4300), 2026-10-15 ~04:02-04:03 +03:00. Both servers were stopped afterwards (frontend-4300 and mock-4010: "stopped").

The mock is **stateless**: writes do not change later reads, and it always returns its example data (card 1 "Spring Boot in depth", IN_PROGRESS, milestones 1 done / 2 open, one note). Checks cover the requests sent and the UI reaction. Anything that depends on stored state is **real-stack** and is for the verifier.

How the steps were driven: `browser_evaluate` ran short DOM scripts that click `data-testid` elements, set input values with input events, and record every XHR (method, URL, body, status) through a hook installed on the page. Snapshots confirmed the dialogs and the structure.

Screenshots: written by the Playwright tool to `run-artifacts/playwright/` (`E2E-M04-01-learning-grid.png`, `E2E-M04-06-learning-after-remove.png`). Copying them into `outputs/evidence/M04/` was denied by the permission layer in this iteration (same as M02/M03), so `result.json` points at the run-artifacts paths.

## E2E-M04-01 [smoke] - Add a learning card (US-LRN-01, SC-001)

Steps
1. Navigate to `http://localhost:4300/learning`. Card `learning-card-1` renders with `learning-status-1` "In progress" and `learning-progress-1` "1/2 milestones".
2. Click `learning-add-button`. Dialog "New learning resource" opens.
3. Set `learning-form-title` = `Kubernetes basics`, `learning-form-description` = `Course notes`. Status left at Not started.
4. Click `learning-form-save`.
5. Captured request: `POST /api/learning-cards` body `{"title":"Kubernetes basics","description":"Course notes","status":"NOT_STARTED"}`, status 201.
6. Dialog closes, `GET /api/learning-cards` 200.
7. Screenshot `E2E-M04-01-learning-grid.png`. Console: no errors.

Test ids used: `learning-add-button`, `learning-form-title`, `learning-form-description`, `learning-form-status`, `learning-form-save`, `learning-form-cancel`, `learning-card-<id>`, `learning-status-<id>`, `learning-progress-<id>`, `learning-expand-<id>`, `learning-edit-<id>`, `learning-delete-<id>`.

## E2E-M04-02 - Title validation (BR8)

Steps
1. Open the add dialog, click `learning-form-save` with the title empty: `mat-error` "Title is required.". No POST.
2. Enter 201 `x` characters into `learning-form-title`, click `learning-form-save`: "Must be at most 200 characters.". No POST.
3. Enter three spaces: "Title is required.". No POST (pattern rejects whitespace-only titles).
4. Click `learning-form-cancel`: dialog closes, no request.

## E2E-M04-03 - Expand a card and add a milestone with a target date (US-LRN-03)

Steps
1. Click `learning-expand-1`. Details show milestone rows `learning-milestone-1`, `learning-milestone-2` with `learning-milestone-done-<id>` and `learning-milestone-delete-<id>`, and the notes `learning-note-1`.
2. Click `learning-milestone-add-1` with the title empty: "Milestone title is required.". No request.
3. Set `learning-milestone-title-1` = `Read chapter 3`, `learning-milestone-target-1` = `2026-11-01`. Click `learning-milestone-add-1`.
4. Captured request: `POST /api/learning-cards/1/milestones` body `{"title":"Read chapter 3","targetDate":"2026-11-01"}`, status 201. Then `GET /api/learning-cards` 200.

## E2E-M04-04 - Complete a milestone (US-LRN-04, D-7)

Steps
1. Click the checkbox of `learning-milestone-done-2` (open in the mock).
2. Captured request: `PUT /api/learning-cards/1/milestones/2` body `{"title":"Build the sample project","done":true,"targetDate":null}`, status 200. Then `GET /api/learning-cards` 200.
3. **Real-stack:** the progress label `learning-progress-1` reads "2/2 milestones" and `learning-status-1` reads "Completed" (status is derived from the milestones, D-7). Verifier to check. Un-ticking returns to "In progress".

## E2E-M04-05 - Add and remove a note (US-LRN-05)

Steps
1. Click `learning-note-add-1` with `learning-note-text-1` empty: "Note text is required.". No request.
2. Set `learning-note-text-1` = `Check the Prism mock output`, click `learning-note-add-1`. Captured `POST /api/learning-cards/1/notes` body `{"text":"Check the Prism mock output"}` 201, then `GET` 200.
3. Click `learning-note-delete-1`. Captured `DELETE /api/learning-cards/1/notes/1` 204, then `GET` 200.
4. **Real-stack:** the new note `learning-note-<nid>` appears with its timestamp and disappears after remove.

## E2E-M04-06 - Remove a milestone; remove a card with confirm (US-LRN-02)

Steps
1. Click `learning-milestone-delete-1`. Captured `DELETE /api/learning-cards/1/milestones/1` 204, then `GET` 200.
2. Click `learning-delete-1`. Confirm dialog "Delete learning resource?" opens with `confirm-cancel` and `confirm-ok`.
3. Click `confirm-cancel`: no request.
4. Click `learning-delete-1` again, then `confirm-ok`. Captured `DELETE /api/learning-cards/1` 204, then `GET /api/learning-cards` 200.
5. **Real-stack:** `learning-card-1` is gone from the grid, and its milestones and notes are gone with it (AC-M04-12).
6. Screenshot `E2E-M04-06-learning-after-remove.png`.
