# E2E scenarios M09 - Shell and navigation (spec 002-visual-polish)

Run with the Playwright MCP against the Prism mock (`scripts/mock.sh start --port 4010`) and the dev server (`scripts/frontend.sh start --api http://localhost:4010`, port 4300). Viewports set with `browser_resize`. Screenshots in `outputs/evidence/M09/`. Mock user: display name "Alex".

Common `data-testid`s used: `nav-dashboard`, `nav-tasks`, `nav-habits`, `nav-learning`, `nav-plans`, `nav-settings`, `nav-collapse-toggle`, `menu-button`, `user-chip`, `plans-start-banner`, `plans-start-banner-dismiss`, `theme-option-light`, `theme-option-dark`, `theme-option-system`, `dashboard-title`, `tasks-title`, `habits-title`, `learning-title`, `plans-title`, `settings-title`.

## E2E-M09-01 [smoke] nav items show icon and label, active item is marked (1440 px)
1. `browser_resize` 1440x900; `localStorage['qf.nav.collapsed'] = 'false'`; open `/dashboard`.
2. For each of the six `nav-*` links: has a `mat-icon`, non-empty label text.
3. Active link (`nav-dashboard`) has class `active`, `aria-current="page"`, accent background.
Result: passed. Dashboard active, all six items have icon and label, `aria-current="page"` on the active item only, background rgb(0, 251, 251) in light.

## E2E-M09-02 collapse to 72 px rail, choice persists, expand restores
1. Click `nav-collapse-toggle`. Expect `.sidenav` width 72, `localStorage['qf.nav.collapsed'] === 'true'`, no label text in `nav-*` links, `aria-label` of links kept (tooltip text).
2. `location.reload()`. Expect width still 72 and the toggle `aria-label` "Expand navigation".
3. Click `nav-collapse-toggle`. Expect width 240, stored `'false'`, labels back.
Result: passed. 72 px after click and after reload; 240 px and labels after expand. Content area moves with the rail (main left 72 + centring at 1440, expanded main left 240).

## E2E-M09-03 390 px: drawer via menu-button, closes after choosing a page, no horizontal scroll
1. `browser_resize` 390x844. Expect `menu-button` present, sidenav closed (left -240).
2. Click `menu-button`. Expect sidenav open (left 0).
3. Click `nav-tasks`. Expect sidenav closed, path `/tasks`, `tasks-title` present.
4. On each of the six pages (`/dashboard`, `/tasks`, `/habits`, `/learning`, `/plans`, `/settings`): `document.documentElement.scrollWidth <= window.innerWidth`.
Result: passed. Drawer open/close verified; scrollWidth == innerWidth == 390 on all six pages (re-checked after the final layout fix).

## E2E-M09-04 1024 px: side navigation, no overlap or clipping
1. `browser_resize` 1024x768 on `/settings`.
2. Expect `menu-button` absent, sidenav position side (left 0, right 240), `main.content` left 240, no overlap.
3. Expect `user-chip` and the theme toggle inside the toolbar (right edge of chip 1008 < 1024), collapse toggle inside the sidenav bounds.
Result: passed.

## E2E-M09-05 user chip shows initials and name, opens /settings
1. At 1440 px, `user-chip` shows avatar text "A" and the name "Alex" (not at phone width).
2. Its `aria-label` is "Profile: Alex".
3. Click `user-chip`. Expect path `/settings` and `settings-title`.
Result: passed.

## E2E-M09-06 plan start banner readable in light and dark, new styling
1. Banner `plans-start-banner` present on each page while the mock plan is "started".
2. Light (`theme-option-light`): background rgba(122, 79, 0, 0.12), text rgb(25, 28, 28), radius 12 px, `schedule` icon present.
3. Dark (`theme-option-dark`): background rgba(245, 195, 91, 0.16), text rgb(224, 227, 226), radius 12 px.
4. Dismiss button `plans-start-banner-dismiss` still present.
Result: passed in both themes (see screenshots `1440-light-settings.png`, `1440-dark-settings.png`).

## E2E-M09-07 contrast-check on the shell, light and dark
1. Set `localStorage['qf.theme']` and reload; run `loops/frontend-dev/outputs/e2e/contrast-check.js` with `browser_evaluate`.
2. Dark run on `/tasks` at 1440 px: checked 45, failures [], unknown [], focus ring 10.12:1.
3. Light run on `/settings` at 1440 px: checked 24, failures [], unknown [], focus ring 6.42:1.
Note: the script walks the whole page, so it covers toolbar and navigation as well. Result: passed, 0 failures in both themes.

- E2E-M01-01: at 1440 px click each of the six `nav-*` links in turn; each opens its `<page>-title`, its link has `active` and `aria-current="page"`. Results: all six pages passed.
