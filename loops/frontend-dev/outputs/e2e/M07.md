## E2E-M07-03 [real-stack-only] - Error state with retry on each page

Written, **not executed** (the mock always returns data). The verifier runs these with the backend stopped, then starts it again.

1. Start the stack: `scripts/backend.sh start --port 8090 --db stable --fresh`, then `scripts/frontend.sh start --api http://localhost:8090`.
2. Stop the backend: `scripts/backend.sh stop --port 8090`. Keep the frontend running.
3. For each page `dashboard`, `tasks`, `habits`, `learning`, `plans`, `settings`: navigate to `/<page>` (reload). Expect `<page>-error-retry` visible inside an error box (`.error-state`). For Settings the load failure shows `settings-load-error`; the page also shows `settings-loading` while fetching.
4. Check `browser_console_messages`: the failed requests appear as errors from the browser (expected, not app errors). No uncaught exception in the Angular log.
5. Click `<page>-error-retry` while the backend is still down: the error stays, the retry request is sent again (`browser_network_requests`).
6. Start the backend again: `scripts/backend.sh start --port 8090 --db stable`. Click `<page>-error-retry`: the error box disappears, the page content (or its empty state, for a fresh database) is shown.
7. Screenshot per page: `E2E-M07-03-<page>-error.png` and `E2E-M07-03-<page>-retry.png`.

Test ids used: `dashboard-error-retry`, `tasks-error-retry`, `habits-error-retry`, `learning-error-retry`, `plans-error-retry`, `settings-error-retry`, `settings-loading`, `settings-load-error`, `<page>-empty-state`.

## E2E-M07-04 - Keyboard navigation

Done in this run with real key presses (`browser_press_key`), plus focus checks with `browser_evaluate`:

1. Focus on `nav-dashboard`, press Tab: focus moves to `nav-tasks`, `:focus-visible` matches, outline `2px solid rgb(63, 81, 181)` (after the fix above).
2. Press Enter on `nav-tasks`: the Tasks page opens, `nav-tasks` has `aria-current="page"`.
3. Press Tab 5 times: focus reaches `tasks-add-button` (order: nav-habits, nav-learning, nav-plans, nav-settings, tasks-add-button). Press Enter: the "New task" dialog opens, focus is on `tasks-form-title` (inside the dialog), `tasks-form-save` is disabled.
4. Press Escape: the dialog closes, focus returns to `tasks-add-button`.
5. The same open-and-close check for the add dialogs, with focus starting on the add button:
   - Habits: `habits-add-button` opens "New habit", focus on `habits-form-name`, Escape returns focus to `habits-add-button`.
   - Learning: `learning-add-button` opens "New learning resource", focus on `learning-form-title`, Escape returns focus to `learning-add-button`.
   - Plans: `plans-create-button` opens "Create plan", focus on `plans-form-title`, `plans-form-save` disabled, Escape returns focus to `plans-create-button`.

6. Settings: focus `nav-settings`, press Enter: Settings opens, `settings-title` present, `nav-settings` has `aria-current="page"`, no load error.
7. Dashboard: focus `nav-dashboard`, press Enter: Dashboard opens. Focus `dashboard-quick-add-task`, press Enter: "New task" dialog opens with focus in `tasks-form-title`. Escape: dialog closes, focus returns to `dashboard-quick-add-task`.

Not walked in this run (open gaps, not failures):
- Habits, Learning and Plans were reached by mouse click, not by Enter on the keyboard. Their nav links are in the Tab order (checked in step 3). Their add dialogs were opened by keyboard (step 5).
- The other dashboard quick-add buttons (Habit, Learning, Plan) were not opened by keyboard.
- The focus trap was checked for first focus only; repeated Tab presses inside a dialog were not tested.
