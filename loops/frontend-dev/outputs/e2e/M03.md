# E2E scenarios - M03 Habits (frontend-dev)

Executed with the Playwright MCP (0.0.40) against the Prism mock (`scripts/mock.sh`, :4010) and the Angular dev server (`scripts/frontend.sh --api http://localhost:4010`, :4300), 2026-10-15 ~03:48-03:50 +03:00. Both servers were stopped afterwards.

The mock is **stateless**: writes do not change later reads, and it always returns its example data (two habits: `Morning run` DAILY not done, `Weekly review` WEEKLY done). Checks therefore cover the requests sent and the UI reaction, not the stored state. Results that depend on stored state are marked **real-stack** and are for the verifier.

How the steps were driven: the Playwright MCP `browser_evaluate` tool ran short DOM scripts that click the `data-testid` elements, set input values with input events, and record every XHR (method, URL, body, status) through a hook installed on the page. Snapshots were used to confirm dialogs and element structure. Screenshots are in `run-artifacts/playwright/` (the Playwright tool only writes there; copying into `outputs/evidence/M03/` was not possible in the earlier iterations either).

## E2E-M03-01 [smoke] - Add a daily habit (US-HAB-01, SC-001)

Steps
1. Navigate to `http://localhost:4300/habits`. Cards `habits-card-1`, `habits-card-2` render.
2. Click `habits-add-button`. Dialog "New habit" opens.
3. Set `habits-form-name` = `Read 20 pages`, `habits-form-description` = `Before bed`. Frequency left at Daily.
4. Click `habits-form-save`.
5. Captured request: `POST /api/habits` body `{"name":"Read 20 pages","description":"Before bed","frequency":"DAILY"}`, status 201.
6. Dialog closes, `GET /api/habits` returns 200.
7. Screenshot `E2E-M03-01-habits-cards.png`. Console: no errors.

Test ids used: `habits-add-button`, `habits-form-name`, `habits-form-description`, `habits-form-frequency`, `habits-form-save`, `habits-form-cancel`, `habits-card-<id>`, `habits-frequency-<id>`, `habits-streak-<id>`, `habits-progress-<id>`, `habits-toggle-<id>`.

## E2E-M03-04 - Toggle completion (US-HAB-03, US-HAB-04)

Steps
1. Click `habits-toggle-1` (Morning run, not done): `POST /api/habits/1/completions` body `{}`, status 201, then `GET /api/habits` 200. Button label is "Mark done" before the click.
2. Click `habits-toggle-2` (Weekly review, done): `GET /api/habits/2/completions?from=2026-10-12&to=2026-10-18` 200, then `DELETE /api/habits/2/completions/2026-10-15` 204 (the newest one in the period), then `GET /api/habits` 200.
3. **Real-stack:** after step 1 the card shows "Done today", the streak goes up by one, the button reads "Undo". After a second toggle the card is undone. Verifier to check.

## E2E-M03-05 - Duplicate completion (BR7)

Steps
1. In the page, override `XMLHttpRequest.prototype.send` so that only `POST /api/habits/<id>/completions` is answered locally with status 409 and body `{"code":"CONFLICT",...}`. No network request is made for that POST, so the browser logs no failed resource (a response override, as allowed by T044). Other requests pass through to the mock.
2. Click `habits-toggle-1`: `POST /api/habits/1/completions` 409 (synthesized).
3. Snackbar shows "Already completed"; `GET /api/habits` 200 (the list refreshes).
4. Screenshot `E2E-M03-05-already-completed.png`. Console: no errors (Vite and Angular dev LOG lines only). `console_errors: 0`.
5. Note for the verifier: on the real stack a genuine 409 is a network response, and the browser logs `Failed to load resource ... 409 (Conflict)`. That browser entry is expected for a real 409 and is not an app error. Do not count it against the real-stack run without checking.

## E2E-M03-06 - Edit, deactivate, delete (US-HAB-05)

Steps
1. Click `habits-edit-2`. Dialog "Edit habit" shows name `Weekly review`, frequency Weekly, `habits-form-active` on. Click `habits-form-save`: `PUT /api/habits/2` body `{"name":"Weekly review","description":null,"frequency":"WEEKLY","active":true}` 200, dialog closes, list reloads.
2. Click `habits-deactivate-1`: `PUT /api/habits/1` body `{"name":"Morning run","description":"30 minutes before work","frequency":"DAILY","active":false}` 200, list reloads.
3. **Real-stack:** the card gets the `inactive` class (dimmed, opacity 0.5), the "Inactive" chip `habits-inactive-1` shows, and `habits-toggle-1` is disabled, so it cannot be completed. The mock is stateless and still returns the card as active, so this is not visible here. The code path is in `habits-page.component.html` and `toggleCompletion` returns early for inactive habits.
4. Click `habits-delete-1`: confirm dialog "Delete habit?" with the habit name, buttons `confirm-cancel` and `confirm-ok`.
   - Cancel: no request sent, dialog closes.
   - OK: `DELETE /api/habits/1` 204, then `GET /api/habits` 200.
5. **Real-stack:** the card disappears and its completions are gone (verifier, with a fresh db).
